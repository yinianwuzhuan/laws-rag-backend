# 法律 RAG 黄金评测集

## legal-rag-v4（新增法律真实问法挑战集）

`datasets/legal-rag-v4.jsonl` 是在扩充到5040个Qdrant向量点后重新人工编写的100题挑战集。它不复用民法典、劳动法和刑法旧题，黄金依据集中覆盖本轮新增的21部法律。

- 数据规模：100道全新可回答题，Dev 66题、Test 34题。
- 数字与期限：20题，覆盖日期、时效、年龄、倍数以及多段期限。
- 相似概念辨析：20题，要求区分相邻制度、不同程序和相似主体。
- 否定与例外：20题，重点测试“不得、不予、除外、不适用、但是”等反向条件。
- 生活化和不规范表达：20题，使用简称、口语、冗余事实和普通用户表达。
- 跨法律与多依据：15题，覆盖实体法/程序法、专项法/责任法的共同适用。
- 精确术语诊断：5题，仅保留少量用于观察BM25词面优势的术语题，不再使用大段原文反向提示答案。
- 分层划分：六类题型分别按约2:1进入Dev/Test，防止某类题只出现在一个分组。
- 困难负例：每题固定3个真实Qdrant负例，共300个，包含同法相邻条文和跨法相同条号。
- 人工审校：问题与黄金法条逐项绑定；生成器只负责读取真实payload、补全答案摘要和负例，不自动拼接问题。

重新校验并生成：

```powershell
& .\eval\tools\build-legal-rag-v4.ps1
```

调整向量、BM25、RRF 或 Reranker 参数时仍然只使用 Dev；方案冻结后再运行 Test。

## labor-criminal-v1（当前默认）

`datasets/labor-criminal-v1.jsonl` 是第二阶段的跨法律检索黄金集，覆盖《中华人民共和国劳动法》《中华人民共和国劳动合同法》和《中华人民共和国刑法》，并在部分场景中引入《中华人民共和国民法典》作为辅助依据或干扰项。

- 数据规模：100题，其中 Dev 66题、Test 34题；98题可回答，2题为需要实时地方标准的边界题。
- 领域分布：劳动法30题、劳动合同法30题、刑法40题。
- 难度分布：84道 `hard`、16道 `medium`。
- 问题类型：45道相似规则辨析题、15道多法条题、14道口语化问题、12道跨法律问题，并包含否定条件、长事实和边界问题。
- 黄金标签：共引用149个不同的 `business_id`；已与当前 Qdrant payload 逐项核对，缺失数为0。
- 语料规模：劳动法原文107条、劳动合同法98条、刑法解析后505条（包括“之一、之二”等插入条文）。
- 当前 Qdrant 中劳动法第37、89、107条各残留两个历史版本的 Point，本评测集避开了这3条作为黄金标签，防止重复 Point 干扰基线解释。
- 题目刻意采用普通劳动者、企业人员和一般公众可能使用的表达，不依赖直接说出罪名或法条号，用于暴露纯向量检索在近义规则、跨法联合和细微条件辨析上的短板。

## civil-code-v2

`datasets/civil-code-v2.jsonl` 在 v1 的60题基础上新增40道高难度题，总计100题，其中 Dev 66题、Test 34题；98题可回答，2题为边界题。

- 保留 v1 全部题目和原有划分，保证历史报告仍可复现。
- 新增题以相似规则辨析、多法条联合、否定条件和长事实场景为主。
- 全集包含57道 `hard`、19道 `near_miss`、16道 `multi_article` 和5道 `long_context` 题。
- v2 与 v1 使用相同的 `civil-code-v1` 语料清单，变化仅发生在黄金评测问题，不需要重新导入向量。
- v1 的 Test 已经用于首次基线；评估 v2 时应以新增的困难题表现和分组指标为重点，不应把整个 v2 Test 视为完全未见数据。

## civil-code-v1

`datasets/civil-code-v1.jsonl` 是基于当前项目实际使用的《中华人民共和国民法典》Markdown 文档编制的第一版黄金评测集。

`corpus/civil-code-v1-manifest.json` 固定了本次评测对应的原始文件、条文范围、业务 ID 规则和 SHA-256；语料发生变化时应升级 corpus/dataset 版本并重新建立基线。

- 语料范围：民法典第一条至第一千二百六十条，共 1260 条。
- 文档粒度：一条法律条文对应一个向量文档。
- 稳定标签：`business_id = source_type + 规范化后的 source_name + article_no_arabic + chunk_index`。例如 `law_中华人民共和国民法典_1047_0`。
- 数据规模：60 题，其中 58 题可由民法典回答，2 题为边界/对抗问题。
- 数据划分：`dev` 用于调整检索方案，`test` 只用于阶段性验收，避免只针对固定题目调参。

### 每条数据的主要字段

| 字段 | 含义 |
| --- | --- |
| `id` | 评测问题的稳定编号 |
| `split` | `dev` 或 `test` |
| `category` | 直接查询、场景改写、多法条、边界或对抗问题 |
| `difficulty` | 人工标注的初始难度 |
| `question` | 实际发送给检索器和 RAG 服务的问题 |
| `answerable` | 在“仅使用民法典”的前提下能否回答 |
| `gold_documents` | 应当召回的标准法条；`relevance=2` 为核心依据，`1` 为辅助依据 |
| `gold_answer_points` | 最终回答至少应覆盖的原子事实 |
| `forbidden_claims` | 回答中不得出现的典型错误或越界结论 |
| `expected_behavior` | 不可回答问题的期望行为 |

### 第一阶段指标

检索评测只统计 `answerable=true` 的数据：

- `Recall@1/3/5`
- `MRR`
- `Precision@5`
- 按编、难度、问题类型分别统计的 Recall@5

不可回答数据单独统计：

- 是否错误命中不存在的条号
- 严格 RAG 模式是否明确说明知识库依据不足
- 是否编造法律名称、条号或法律结论

生成评测后续再加入：

- 答案要点覆盖率
- 引用准确率与引用完整率
- 原文引用一致性
- 有据性/忠实度
- 正确拒答率

### 使用约束

1. 调整 embedding、TopK、过滤、混合检索或重排时，只看 `dev` 集。
2. 确定方案后再运行 `test` 集并保存报告。
3. 不要因为某题未命中就直接改写该题标签；先检查标准法条、原始文档、入库 payload 和实际用户意图。
4. 评测前应先运行 Qdrant 存量迁移，使数据库 payload 与本评测集使用同一套业务 ID 规则。
